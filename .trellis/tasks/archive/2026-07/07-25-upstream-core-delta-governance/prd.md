# 上游核心差异治理与兼容 CI

## Goal

建立上游核心差异登记、预算、兼容矩阵与 CI 门禁，防止未经授权的核心生产代码差异增长。

## Requirements

- 登记 `packages/dom-to-figma/src` 相对选定上游基线的全部现存生产代码差异。
- 每个登记项包含能力、路径、来源提交、通用性判断、测试、责任人、复核日期、上游状态和删除条件。
- 生产代码定义为 `src` 下的运行时代码；测试、fixtures 和 snapshots 必须报告，但不计入严格生产差异预算。
- CI 必须检测新增路径以及已登记 patch 内容的变化；只有显式更新登记证据后才能通过审查。
- 最新稳定上游版本兼容检查必须阻断日常变更；本地解析后的 `upstream/main` 检查日常为 advisory、同步 PR 为 blocking。
- 报告必须显示精确 ref/version、文件数、增删行、能力分组和未登记项，不能只输出成功或失败。
- 当前基线为 20 个核心 `src` 变更文件；阶段预算为不高于 10、不高于 5、上游接受后接近 0。
- 预算失败不得通过删除行为或弱化 parity 测试解决。

## Acceptance Criteria

- [x] 当前 20 个核心变更文件均能映射到登记项，且没有无所有者的生产差异。
- [x] 在测试分支中新增未登记核心生产文件或修改已登记 patch 时，门禁稳定失败并给出修复提示。
- [x] 仅测试/fixture 变化不会被误报为未登记生产差异，但仍出现在报告中。
- [x] 最新稳定版矩阵为 blocking，`upstream/main` 在普通 PR 与同步 PR 中分别表现为 advisory 和 blocking。
- [x] CI 记录移动 ref 解析后的 commit SHA，结果可复现。
- [x] `docs/fork-maintenance.md` 说明登记、预算、豁免审批和同步流程。
- [x] 没有引入自动同步或直接修改 fork `main` 的机制。

## Notes

- 本任务是其他五个子任务的前置条件。
- 任何豁免都必须有到期日期；永久通配路径不符合要求。
